# Hearth — Valheim: ванильный сервер или Valheim Plus, с веб-панелью

Docker Compose для Linux x86-64 или Docker Desktop в режиме Linux containers. В комплекте исходный код русскоязычной панели, Dockerfile, настройки и тесты. Игровые файлы загружаются из Steam при первом запуске; при выборе режима V+ мод загружается из официального GitHub Grantapher. Ванильный режим работает без модов и BepInEx.

При первой установке и по кнопке обновления автоматически выбирается текущий стабильный сервер Steam, а для режима V+ — [последний стабильный релиз Valheim Plus от Grantapher](https://github.com/Grantapher/ValheimPlus/releases/latest). BepInEx входит в пакет мода. Вводить номера версий не нужно.

## Быстрый запуск

1. Установите Docker Engine и Docker Compose v2+ на целевой машине. Практический стартовый бюджет: 4 CPU, 8 ГБ RAM и 30 ГБ свободного SSD; большой мир и резервные копии потребуют больше. Во время проверки обновления одновременно работают основной сервер и временный тестовый сервер.
2. Распакуйте эту папку и перейдите в неё.
3. Скопируйте `.env.example` в `.env`:

   ```sh
   cp .env.example .env
   ```

   В PowerShell: `Copy-Item .env.example .env`.

4. Замените `SERVER_PASSWORD` и `PANEL_PASSWORD`. Пароль панели — минимум 16 символов, игры — минимум 5. Не используйте пароль игры как часть названия сервера. Значения с `$` в `.env` заключайте в одинарные кавычки, чтобы Compose не выполнял подстановку. Задайте `SERVER_NAME`, `WORLD_NAME`, `SERVER_MODE` (`plus` или `vanilla`) и адреса сайта/подключения до первого запуска. Для Loki сохранены прежние значения по умолчанию.
5. Запустите:

   ```sh
   docker compose up -d --build
   ```

6. Откройте [админ-панель](http://localhost:8080/admin) и войдите с `PANEL_PASSWORD`. Первая установка занимает несколько минут; ход загрузки виден в консоли панели.
7. Для игроков откройте/пробросьте **UDP 2456–2457**. Подключение в игре: `IP_СЕРВЕРА:2456`.

Для удалённого сервера панель по умолчанию доступна через SSH-туннель:

```sh
ssh -L 8080:127.0.0.1:8080 user@server
```

После этого откройте `http://localhost:8080/admin` на своём компьютере. Для постоянного доступа через домен используйте HTTPS reverse proxy, направленный на `127.0.0.1:8080`, и задайте `COOKIE_SECURE=1`. Панель не следует публиковать в интернет по обычному HTTP. TLS-прокси в комплект не включён; настройте имеющийся reverse proxy для домена `loki.ach-play.ru`.

## Публичная страница сервера

Главная страница `/` — лендинг для игроков. Админ-панель переехала на `/admin`; пароль администратора и защита API сохранены. На главной есть северный пейзаж, описание мира, инструкция подключения, копирование адреса, ссылки на сообщество и, только в режиме V+, клиентский мод, вопросы и ответы. Внешние шрифты, трекеры и библиотеки не загружаются.

Начальные данные: **Loki**, адрес игры **loki.ach-play.ru:2456**, сообщество **http://discord.ach-play.ru**. Имя в игровом списке задаётся отдельно в настройках сервера; для новой установки `.env.example` тоже использует Loki.

В **Настройки → Лендинг** можно изменить домен сайта, название, описание, адрес подключения и ссылку сообщества. Сохранение не останавливает игру; предыдущая конфигурация остаётся в `config/hearth-settings.previous.json`. Пустой адрес отключает копирование, пустая ссылка скрывает кнопку сообщества. Сведения на этой вкладке публичные: не размещайте в описании пароли.

Публичный `/api/public` отдаёт только название, описание, адрес подключения, адрес сайта, ссылку сообщества, режим, признак публичного списка, факт работы процесса, количество игроков при свежем ответе A2S и установленные версии. Имена игроков, журнал, файлы, копии, пароли и конфигурация не публикуются. Без свежего ответа A2S онлайн обозначается прочерком, а не нулём. Ссылка загрузки V+ ведёт на **установленную** версию сервера, чтобы игрок не скачал несовместимый latest.

Для размещения на домене направьте веб-трафик `loki.ach-play.ru` через свой HTTPS reverse proxy на порт панели, а UDP 2456–2457 — на игровой сервер. Запись адреса в панели не меняет DNS, firewall или маршрутизацию. Если DNS-провайдер проксирует HTTP, игровой поддомен должен также обеспечивать прямой доступ к UDP. При работе через HTTPS задайте `COOKIE_SECURE=1`. Если веб-прокси в другом контейнере, используйте доступный ему адрес сервиса вместо его собственного localhost.

## Поиск сервера и сайта

Сборка по умолчанию использует `REQUIRE_PUBLIC_LISTING=1`: рабочий игровой процесс всегда запускается с `-public 1`, даже если в сохранённых настройках раньше была выбрана закрытая видимость. Тестовый мир проверки обновления остаётся закрытым. Если включено «Добавлять сайт к имени в списке», к публикуемому имени добавляется адрес из настроек лендинга (по умолчанию `https://loki.ach-play.ru`); например, **Loki | https://loki.ach-play.ru**. Имя для поиска показано в настройках и в инструкции подключения. В игровом списке URL является частью имени: клиент игры может не делать его кликабельным. На сайте и в панели добавлены обычные ссылки.

Это запрос публикации в Steam, а не подтверждение наличия в глобальной выдаче. Для обнаружения нужен запущенный сервер, прямой доступ к нему по UDP 2456–2457, подходящий NAT/firewall и связь со Steam. Домен игрового сервера должен вести на его публичный IP; обычный HTTP-прокси игровой UDP не обслуживает. Внешний поиск через Steam и реальный вход на целевой сервер из этой среды не проверены. См. [параметры публикации Valheim](https://www.valheimgame.com/support/a-guide-to-dedicated-servers/).

Для намеренно закрытого локального сервера задайте `REQUIRE_PUBLIC_LISTING=0` в `.env` и отключите видимость в панели: тогда настройка видимости снова редактируется. Ссылка добавляется только для публичного сервера и при включённом переключателе ссылки. Изменение переменной применяется после `docker compose up -d`; уже работающая игра должна перезапуститься с новыми аргументами.

Для веб-поиска подготовлены серверный HTML с названием, описанием и адресом подключения, canonical и Open Graph на адрес сайта из настроек лендинга, `/robots.txt` и `/sitemap.xml`. Админ-панель и API имеют `noindex`; административные API по-прежнему требуют вход. Запрет индексации не заменяет авторизацию.

После размещения сайта на HTTPS-домене подтвердите права на него в [Google Search Console](https://search.google.com/search-console/) и [Яндекс Вебмастере](https://webmaster.yandex.ru/) и отправьте карту `https://loki.ach-play.ru/sitemap.xml`. Эти действия требуют аккаунтов владельца домена и в сборке автоматически не выполняются. Индексацию и позиции определяют поисковые системы; подготовка сайта не гарантирует появление в выдаче. [Руководство Google](https://developers.google.com/search/docs/fundamentals/seo-starter-guide).

## Точность статистики и состояние мира

- Онлайн берётся из Steam A2S_INFO, опрос — раз в 10 секунд. Отсутствие ответа показывается как неизвестное состояние, а не ноль игроков.
- Входы берутся из сообщения `Got character ZDOID from …`. Это счётчик по имени персонажа, не по SteamID. Изменения формата логов могут потребовать правки парсера. Записи о разрывах соединений сохраняются как сообщения игры: панель не приписывает их игроку без достоверного соответствия.
- Время учитывается только между двумя успешными опросами, где видно одно и то же имя. A2S_PLAYER может не возвращать имена в Valheim; тогда этот показатель останется нулевым. Переименования и одинаковые имена не различаются. Это приблизительная статистика с момента установки панели, а не история персонажа.
- Состояние мира здесь означает состояние сохранений. День мира, побеждённые боссы, карта, навыки, убийства и смерти не извлекаются. Для такой телеметрии потребуется дополнительный серверный плагин; он не включён.
- `SERVER_PUBLIC=0` может ограничить работу A2S. Плановые копии при запущенном сервере и неизвестном онлайне откладываются.
- Crossplay в этой сборке не включён. Клиенты должны поддерживать моды и иметь совместимую связку Valheim/V+/BepInEx. Инструкция автора: [INSTALL.md](https://github.com/Grantapher/ValheimPlus/blob/master/INSTALL.md). На Thunderstore версия V+ называется `10.2.0`, на GitHub — `0.10.2.0`.


## Свой домен и несколько серверов

В **Настройки → Лендинг** задаются адрес сайта, название, описание мира, адрес подключения и ссылка сообщества (Discord, Telegram или другая страница). Ссылку сообщества можно оставить пустой. Адрес сайта — HTTP(S)-домен или IPv4 с необязательным портом, без пути, query и fragment. Он используется для canonical, Open Graph, robots.txt, sitemap.xml, инструкции установщиков и ссылки в имени сервера. Данные не берутся из недоверенного заголовка Host. Ссылки лендинга обновляются сразу, имя уже запущенного сервера — после перезапуска игры. DNS, сертификат, nginx и firewall изменяются отдельно.

В **Настройки → Сервер** доступны режим следующей установки (`Valheim Plus` / `Ванильный`) и переключатель ссылки в имени. Длинный URL (больше 70 символов) в Steam-имя не добавляется, чтобы сохранить ограничение имени 80 символов. Ванильный режим запускает обычную игру без V+ и BepInEx. Лендинг показывает инструкции для обычного клиента, скрывает установщики мода; редактор V+ недоступен. Правила мира и резервные копии доступны в обоих режимах. Описание мира редактируется отдельно и не переписывается при смене режима.

Сохранение режима не удаляет старые файлы и не переключает работающий релиз: после сохранения нажмите **Обновления → Установить последние версии**. Панель показывает выбранный режим и предупреждает, если сейчас установлен другой. Публичная страница до завершения переключения показывает фактически установленный режим. Для нового сервера без установленного релиза используется выбранный режим. Переход с модифицированного мира на обычный может изменить игровые возможности; для независимого ванильного мира предпочтительна отдельная копия.

Начальные значения задаются через `.env`: `SERVER_MODE`, `SITE_URL`, `SITE_TITLE`, `SERVER_ADDRESS`, `COMMUNITY_URL`. Сохранённые настройки панели имеют приоритет. Старые установки без поля режима считаются V+, остальные новые поля получают совместимые значения по умолчанию.

Для второй копии на том же хосте используйте **отдельное имя проекта Compose, пару UDP-портов и порт панели**. Отдельное имя проекта создаёт независимый том `game`; не подключайте к двум игровым процессам один том.

```bash
cp .env.vanilla.example .env.vanilla
# В .env.vanilla замените пароли, домен и адрес на свои значения.
docker compose --env-file .env.vanilla -p valheim-vanilla up -d --build
```

Пример использует vanilla, мир `VanillaWorld`, UDP `2466–2467` и локальный порт панели `8081`. Первый сервер может продолжать работать на `2456–2457` и `8080`. Для команд управления второй копией всегда повторяйте `--env-file .env.vanilla -p valheim-vanilla`. Имена проектов не должны совпадать. Команду `down -v` для действующих миров не используйте: она удаляет их тома.

`GAME_PORT` задаёт игровой порт внутри и снаружи контейнера; `GAME_QUERY_PORT` должен быть ровно на единицу больше. Диапазон первого — 1024–65534. `PANEL_BIND`/`PANEL_PORT` задают публикацию веб-панели. Порты видны в настройках для справки, изменяются через `.env` и `docker compose ... up -d`. При смене игрового порта обновите также адрес для игроков на лендинге, firewall и маршрутизацию. Порты проверяются при старте менеджера.

Windows-установщик позволяет ввести HTTPS-адрес сайта нужного сервера перед проверкой и установкой. Linux-установщик принимает `--server https://vanilla.example.com` (для ванильного сервера установка V+ будет отклонена). Скачивание пакета всегда идёт из официального репозитория Grantapher, с проверкой SHA-256; серверный API не может подменить источник архива. Для установки модов используются только HTTPS-сайты на порту 443, без перенаправления API на другой домен.

## Как устроено обновление

1. Нажмите **«Установить последние версии»**. Для ванильного режима скачивается только текущая public-ветка Steam; проверки GitHub, V+ и BepInEx не выполняются. Проверка запуска, копии и откат работают в обоих режимах. Следующие пункты о моде относятся к режиму V+. Панель запросит последний стабильный релиз V+ через GitHub Releases; предварительные релизы не устанавливаются.
2. Из описания мода определяется поддерживаемая версия игры. Если сведения отсутствуют или неоднозначны, операция отменяется с сообщением.
3. SteamCMD скачает текущую public-ветку приложения `896660` в отдельный каталог. Рабочий сервер продолжает работать.
4. Панель скачает `UnixServer.zip` выбранного релиза Grantapher, включая BepInEx, и проверит SHA-256. Для 0.10.2.0 хеш закреплён в коде; для новых релизов используется digest GitHub.
5. Кандидат запустится на временном мире. Проверяются версии игры/V+, загрузка BepInEx 5, готовность сервера и отсутствие ошибок загрузки. На запуск отводится 180 секунд.
6. Если отличается только версия игры, во вкладке **«Обновления»** появится **«Одобрить эту пару и обновить»**. Это разрешение на одну попытку для фактической версии игры, версии мода и SHA-256 архива. Оно действует 30 минут и теряется при перезапуске панели. При подтверждении файлы скачиваются и проверяются повторно; другая пара требует нового одобрения. Ошибки запуска или SHA-256 одобрением не обходятся. Например, для Steam 1.0.16 и V+ 0.10.2.0, заявляющего 1.0.15, решение принимает администратор; панель не утверждает официальную совместимость.
7. После проверки рабочий сервер мягко остановится, будет создана копия мира и конфигурации. Панель переключит релиз и дождётся готовности основного мира (до 180 секунд, затем 5 секунд наблюдения).
8. При неудачном запуске панель автоматически попробует вернуть прежний релиз, мир и конфигурацию. Изменённый новым сервером мир предварительно сохраняется отдельно. Если контейнер перезапустится до подтверждения запуска, при следующем старте также будет выполнен откат. Если мягкая остановка или восстановление не удастся, панель покажет ошибку и имя копии; принудительное завершение игрового процесса не применяется.
9. Предыдущий релиз и копия остаются для ручного отката после успешного обновления. Проверка запуска не гарантирует совместимость всех игровых механик или подключения клиентов. Поздние ошибки после завершения проверки автоматически не откатываются. При первой установке предыдущего релиза нет: неудачно запущенный процесс останавливается.

Версии определяются заново при каждом нажатии кнопки. Существующий установленный сервер не обновляется сам при перезапуске контейнера. Режим запуска определяется метаданными установленного релиза; сохранённый выбор режима применяется при следующем обновлении. При откате возвращается прежний режим релиза; выбранный режим следующей установки может отличаться. Старые `GAME_VERSION` и `MOD_VERSION` в `.env` больше не используются, их можно удалить. Получение исторических сборок и выбор бета-веток не предусмотрены.

## Резервные копии и откат

- `BACKUP_HOURS=6`: проверка необходимости плановой копии раз в 6 часов. Если игроки есть или онлайн неизвестен, копия ждёт пустого сервера. `0` отключает расписание.
- Перед любой копией работающий сервер получает SIGINT. Панель ждёт до 120 секунд. Если процесс завис и не завершился, операция отменяется: неполная копия не выдаётся за согласованную.
- Копирование останавливает сервер на время упаковки. После ручной/плановой копии ранее работавший сервер запускается вновь.
- Хранятся последние `BACKUP_KEEP=12` **плановых** копий. Ручные копии, копии перед обновлением и перед восстановлением не удаляются автоматически. Релизы также сохраняются; следите за местом на диске.
- Обычное восстановление разрешено для копии текущего релиза. Полный откат возвращает предыдущий релиз и его мир одновременно, чтобы не запускать старый сервер на уже преобразованном мире.
- Перед восстановлением текущий мир сохраняется отдельно. Восстановленный сервер запускается автоматически.
- Копия содержит `saves/`, `config/` и `manifest.json`. Бинарные файлы игры, `.env`, журнал панели и база статистики не входят в скачиваемый архив. Для аварии всего хоста дополнительно сохраняйте том Docker, `.env` и эту сборку на другом устройстве.

## Данные и настройка V+

### Меню «Настройки»

В панели откройте **Настройки → Сервер / Мир / Valheim Plus**. Кнопка «Перечитать» загружает значения с диска. Фоновое обновление статистики не стирает ввод в редакторе.

- **Сервер:** название, новый пароль игры (пустое поле сохраняет текущий), показ в списке серверов, период автосохранения, число и интервалы встроенных копий Valheim. Порты, пароль администратора панели и расписание архивов панели остаются в `.env`/Compose.
- **Мир:** имя выбирает сохранение; новое имя создаст новый мир при запуске, а не переименует старый. Для каждого имени сохраняется собственный профиль. По умолчанию панель не управляет правилами существующего мира. Если включить управление, сначала применяется выбранный набор правил, затем отдельные модификаторы и дополнительные флаги. Выключение управления оставляет уже записанные в мире правила; для сброса выберите «Обычный», уберите исключения и дополнительные флаги и примените. Флаги дополняют набор: например, набор «Погружение» может сам отключать карту. Seed и прогресс боссов не редактируются.
- **Valheim Plus:** редактор читает фактический CFG после первого запуска мода. Сохраняет комментарии, порядок разделов и остальные параметры. Числа, переключатели и объявленные модом диапазоны проверяются на сервере. Все параметры поставляемого файла 0.10.2.0 имеют русские подписи; новые неизвестные параметры будущих версий показываются с техническим именем. Не забудьте включить раздел V+, который настраиваете.

Под параметрами сервера и V+ показаны короткие русские пояснения, формат ввода, допустимые значения и исходные значения. Диапазоны V+ берутся из метаданных установленного CFG, ограничения сервера — из проверки панели. Если мод не объявил игровой диапазон, это указано явно: технический предел ввода не считается безопасным игровым диапазоном. Русские пояснения подготовлены по V+ 0.10.2.0; исходный комментарий установленной версии доступен в раскрывающемся блоке. Поиск учитывает также русские описания.

Каждая вкладка сохраняется отдельно. Для игровых вкладок перед сохранением игровой процесс мягко останавливается и создаётся архив `pre-config`. «Сохранить без запуска» оставляет игру остановленной; «Сохранить и запустить» запускает установленный сервер после записи. Игроки при этом отключаются. Изменения других вкладок не сохраняются: в подтверждении это указано явно.

Панель отвергает устаревшую форму, если файл изменился после загрузки страницы. В таком случае перечитайте конфигурацию. Неизвестные ключи, неправильные типы и попытки вставить новые строки через значения отклоняются.

Настройки сервера и профили миров хранятся в `/data/config/hearth-settings.json` и имеют приоритет над `SERVER_NAME`, `WORLD_NAME`, `SERVER_PASSWORD`, `SERVER_PUBLIC` из `.env`. Эти переменные служат начальными значениями до первого сохранения серверных/мировых настроек. Новая конфигурация входит в резервные копии и восстанавливается вместе с миром. Архив конфигурации содержит пароль игры; пароль панели в него не входит.

### Файлы

Все постоянные данные находятся в именованном томе Compose `game`:

```text
/data/
  releases/     # отдельные установки игры и мода
  saves/        # сохранения и списки доступа Valheim
  config/       # BepInEx / V+ и hearth-settings.json с настройками панели
  backups/      # архивы мира и конфигурации
  logs/         # консоль, 10 МБ × 4 файла
  panel.sqlite  # статистика и последние 50 000 событий
  state.json    # текущий релиз и точка отката
```

V+ использует настройки по умолчанию автора. Баланс игры в этой сборке не меняется. После первого запуска конфигурация появится в `/data/config/`; в актуальном V+ это обычно `org.bepinex.plugins.valheim_plus.cfg`. Посмотреть имена:

```sh
docker compose exec valheim ls -la /data/config
```

Для редактирования используйте вкладку Valheim Plus. Если требуется ручное редактирование файла, остановите игровой процесс через панель, скопируйте нужный файл на хост, отредактируйте и верните его:

```sh
docker compose cp valheim:/data/config/org.bepinex.plugins.valheim_plus.cfg ./valheim-plus.cfg
# Отредактируйте valheim-plus.cfg
docker compose cp ./valheim-plus.cfg valheim:/data/config/org.bepinex.plugins.valheim_plus.cfg
```

Проверьте, что файл доступен UID 10001 для записи; при необходимости исправьте владельца командой `docker compose exec --user root valheim chown 10001:10001 /data/config/org.bepinex.plugins.valheim_plus.cfg`. Затем запустите игру из панели. Настройки уже существующих файлов не заменяются дефолтами при обновлении.

Для переноса своего мира остановите игровой процесс через панель и скопируйте сохранение в `/data/saves/worlds_local/`, сохраняя всю структуру каталога версии 1.0 и имя `WORLD_NAME`. Не удаляйте исходный мир до проверки входа и сохранения на новом сервере.

## Эксплуатация

```sh
docker compose ps
docker compose logs --tail=100 valheim
docker compose exec valheim tail -n 100 /data/logs/server.log
docker compose stop
docker compose start
```

Обычный `docker compose down` сохраняет том. **`docker compose down -v` удаляет все данные тома**, включая мир, копии и статистику.

Healthcheck проверяет доступность панели. Готовность игры смотрите отдельно по A2S и игровому логу. `restart: unless-stopped` перезапускает контейнер после его сбоя; падение только игрового процесса требует запуска из панели. Отсутствие автоматического перезапуска игры предотвращает бесконечный цикл при повреждённом мире или несовместимом конфиге.

При перезапуске контейнера уже установленный сервер запускается автоматически, даже если до этого был остановлен кнопкой панели. Не перезапускайте контейнер во время обновления/восстановления; для штатной остановки отведено 3 минуты, а загрузка Steam может занимать дольше.

## Проверка сборки

```sh
python -m unittest discover -s tests -v
node --check app/static/app.js
node --check app/static/settings.js
node --check app/static/mod-ru.js
docker compose --env-file .env config --quiet
```

Проверки покрывают авторизацию, CSRF, выход из сессии, ограничение входов, защиту путей архивов, базовую статистику, блокировку параллельных операций, согласованные копии, восстановление и полный откат. Проверен вход в панель в браузере.

Пройдены 62 автоматических теста внутри Linux-образа. В Docker проверены загрузка игры через SteamCMD, запуск Valheim 1.0.15 с V+ 0.10.2.0, применение правил мира и сохранение конфигурации через браузер. Реальный игровой клиент не подключался; A2S на закрытом тестовом сервере не ответил. Подробности и границы проверки — в [VALIDATION.md](VALIDATION.md).

Для обновления самой панели замените файлы сборки в прежней папке, сохранив свой `.env`, затем выполните `docker compose up -d --build`. Сохраняйте прежнее имя Compose-проекта: от него зависит выбор тома с миром.

Если сборка сообщает, что индекс Debian «not valid yet», проверьте часы хоста и Docker и повторите загрузку позже. Для подтверждённого небольшого расхождения доступен ограниченный допуск, например `docker compose build --build-arg APT_MAX_FUTURE_TIME=14400` (4 часа), затем `docker compose up -d`. По умолчанию допуск — 10 секунд; проверка подписей остаётся включённой.

## Установщик мода для игроков Windows

На втором шаге лендинга есть кнопка **«Скачать для Windows»**. Файл `/downloads/Loki-Mod-Installer.exe` доступен без входа в админ-панель. Это самостоятельное русское приложение для Windows 10/11 x64: .NET и Python на компьютере игрока не нужны.

Установщик ищет Valheim (Steam AppID 892970) в реестре Steam, `libraryfolders.vdf` и манифестах библиотек, включая нестандартные диски и русские имена папок. Если поиск ничего не нашёл, игрок выбирает папку с `valheim.exe` вручную. При нескольких установках доступен список.

Он получает **фактически установленную на Loki версию** через `/api/public` выбранного сайта (по умолчанию `https://loki.ach-play.ru`), скачивает соответствующий `WindowsClient.zip` из официального репозитория Grantapher, проверяет SHA-256, безопасные пути архива и версию DLL. Перед изменением клиента повторно проверяет версии сервера. Недоступный API, отсутствие установленного мода, изменившаяся версия или отсутствующая контрольная сумма останавливают установку — подмена на latest не выполняется. Для 0.10.2.0 контрольная сумма закреплена в исходниках, для следующих версий используется SHA-256 GitHub release asset.

Закройте игру перед установкой. Окно показывает версии сервера и локального V+. Уже существующие конфигурации BepInEx сохраняются, другие моды не удаляются. Совместимость сторонних модов не гарантируется; дополнительные копии V+ и другая основная версия BepInEx блокируют установку с пояснением. Папки-ссылки/junction не поддерживаются. Установщик не обновляет саму игру — нужная версия Valheim отображается в окне, обновления игры выполняет Steam.

Перед заменой файлов создаётся копия в `<папка Valheim>/.loki-installer/backups/`. При ошибке копирования выполняется откат. Кнопка **«Восстановить файлы»** отменяет последнюю установку, в том числе прерванную; файлы, изменённые пользователем после установки, безусловно не перезаписываются. Сохранения миров и персонажей установщик не трогает. Игра и Steam принудительно не закрываются. Права администратора автоматически не запрашиваются.

Для работы у игроков сначала опубликуйте этот стек на `https://loki.ach-play.ru` с действующим HTTPS и завершите установку сервера. Прокси должен пропускать `/api/public` и `/downloads/`. Локальный предпросмотр не подменяет домен в установщике. В Windows укажите адрес нужного сайта в поле установщика; в Linux передайте `--server https://your-server.example`. Требуется HTTPS на порту 443. Для ванильного сервера установка мода отклоняется.

EXE пока **без цифровой подписи издателя**; Windows может показать предупреждение о неизвестном приложении. Контрольная сумма опубликована рядом, по ссылке SHA-256. Для публичного выпуска с подписью понадобится сертификат подписи кода; после подписи обновите файл `.sha256`. Никакие защиты Windows установщик не отключает.

Исходники находятся в `installer/`. Для пересборки на Windows нужен .NET SDK 10:

```powershell
./installer/build.ps1
```

Затем пересоберите Docker-образ, чтобы он раздавал новый EXE. Проверки логики установки запускаются отдельно, с официальным WindowsClient.zip версии 0.10.2.0:

```powershell
dotnet run --project installer-tests/Tests.csproj -- C:/Downloads/WindowsClient.zip
```

Тесты работают во временной папке с макетом игры и не изменяют установленный Steam-клиент.

## Linux-установщик для Steam / Proton

На лендинге добавлена отдельная кнопка Linux / Proton, ссылка SHA-256 и раскрывающаяся инструкция. Скачиваемый файл: `/downloads/Loki-Mod-Installer-Linux.sh`. Это один читаемый скрипт с русским диалогом в терминале; нужны Linux x86_64 и Python 3.9+. Он запускается от обычного пользователя, без sudo, не устанавливает системные пакеты.

1. В Steam → Valheim → Свойства → Совместимость включите Proton и дождитесь загрузки Windows-версии игры. Закройте игру.
2. Скачайте Linux-установщик. Откройте терминал в папке загрузки и выполните:

   ```bash
   bash Loki-Mod-Installer-Linux.sh
   ```

3. Выберите папку из найденных библиотек Steam или введите путь вручную. Поддерживается поиск обычного Steam, Steam Flatpak, Steam Snap и дополнительных библиотек из `libraryfolders.vdf`. Проверяются манифест Steam AppID 892970 и наличие Windows-клиента x64. Корневая ссылка Steam разрешается; ссылки внутри дерева модов и конфликтующие по регистру имена отклоняются.
4. Подтвердите установку. Нужная версия берётся из публичного API Loki; загружается **WindowsClient.zip**, а не Linux-серверный пакет. Проверяются HTTPS-источник, SHA-256, структура архива и Windows DLL. Номер версии сервера повторно сверяется перед записью. Саму игру обновляет Steam.
5. В Steam → Valheim → Свойства → Общие → Параметры запуска укажите:

   ```text
   WINEDLLOVERRIDES="winhttp=n,b" %command%
   ```

   Если параметры уже заданы, сохраните их. Переменная окружения ставится перед `gamemoderun`, `mangohud` или другой командой; `%command%` остаётся один раз. Если уже есть `WINEDLLOVERRIDES`, дополните его значение через `;`, например `WINEDLLOVERRIDES="version=n,b;winhttp=n,b" %command%`. Настройка нужна и Steam Flatpak. Установщик не переписывает файлы настроек Steam. [Описание загрузки BepInEx через Proton](https://docs.bepinex.dev/master/articles/advanced/steam_interop.html).
6. Запустите Valheim через Steam. Проверить загрузку V+ можно по `BepInEx/LogOutput.log` в папке игры.

Существующие конфигурации сохраняются. Копии заменяемых файлов и журнал установки лежат в `<Valheim>/.loki-installer-linux/backups/`. При ошибке копирования производится откат. Отмена последней установки:

```bash
bash Loki-Mod-Installer-Linux.sh --restore
```

Можно явно задать папку: `bash Loki-Mod-Installer-Linux.sh --game "/путь/к/Valheim"`. Команда `--launch-options` повторно показывает инструкцию для Steam. При восстановлении файлы, изменённые после установки, не заменяются автоматически. Если BepInEx был удалён при откате, удалите добавленный `winhttp` из параметров Steam. Прочие параметры сохраните. Сохранения и Proton-префикс не изменяются; Protontricks не требуется.

Исходники и тесты находятся в `installer-linux/`; сборка скачиваемого файла: `python3 installer-linux/build.py`. После обновления файлов проекта на сервере выполните `docker compose up -d --build` (контейнер и игровой сервер перезапустятся). Данные игрового тома сохраняются. Публикация на реальном сервере не выполняется автоматически из этой рабочей папки.

Проверки логики установки выполнены в Linux-контейнере на макете папки игры с настоящим WindowsClient.zip. Запуск графического клиента через Proton и вход на сервер требуют отдельной проверки на Linux-компьютере со Steam.
